# Authority

This chapter defines principals and their keys, the signers and verification of signatures, the capability kinds NaN OS adds to NaN's, grants with their objects, rights and caveats, delegation and child principals, revocation and expiry, the construction of an instance's Env, the authority of sessions, provenance classes, placement in the shared and isolated spaces with the trust rule of machines without `iommu`, the confidentiality rule of the shared space, the costs of isolation, and the `auth` and `place` code families.

## Principals

A **principal** is who acts and is accountable. Its name has the form [principals](02-identifiers.md#principals) gives, and its prefix fixes its kind:

| Kind | Name | Key | Created by |
| --- | --- | --- | --- |
| owner | `owner` | Ed25519, private half off the machine | [claim](19-oversight.md#claim) |
| human | `human.<name>` | Ed25519, off the machine | [enrollment](19-oversight.md#enrollment) |
| agent | `agent.<name>` | Ed25519, off the machine | enrollment |
| child | `<parent>.<segment>`, its parent a human, an agent or a child | Ed25519, generated by `keys` | [delegation](#delegation) |
| instance | `inst.<moniker>` | none | its spec |
| builder | `builder.<name>` | Ed25519, off the machine | enrollment |
| vendor | `vendor.<name>` | Ed25519, off the machine | genesis, from the loader's vendor keys, or enrollment |
| system | `system` | none | genesis |

Every principal other than `inst.*` and `system` has a **principal record** at `/sys/principals/<name>`, using the [types](02-identifiers.md#types) of identifiers:

```nan
pub closed struct PrincipalRecord derives Encode {
    pub key: Option[Array[u8, 32]] // current Ed25519 public key
    pub former: mem::List[Array[u8, 32]] // keys replaced by rotation, in rotation order
    pub parent: Option[Principal] // the delegator of a child
    pub expires_utc_ns: Option[i64] // always set for a child
} PrincipalRecord
```

- `inst.<moniker>` exists exactly while the instance's spec does, at `/sys/instances/<moniker>` or, for a job, `/state/<moniker>/job`; `system` always exists. The owner's record mirrors the owner key the loader keeps ([floor and owner key storage](03-boot.md#floor-and-owner-key-storage)).
- The plan step `delete /sys/principals/<name>`, taken by `owner` or under a `Principals` grant with `enroll` covering the name, removes the principal, its children and every grant they and it hold, in one commit. It is refused while an instance acts for one of them (`auth.principal-in-use`).

Each instance **acts for** one principal: the `principal` field of its spec, or for a job the principal of the plan that ran it or, for an [extraction](19-oversight.md#extraction), of the session requesting it. Its commits name that principal, on whose authority they are made, and its moniker ([commits](11-store.md#commits)). A plan writes specs acting for its own principal, and an `owner` plan also for `system`. An instance writing a spec through its `Control` capability gives it the principal the instance acts for, or any principal when that is `system`. A spec acting for a child principal, or for a principal its writer may not name, is refused (`auth.wrong-principal`). Base instances act for `system`.

## Keys and signatures

### Keys on the machine

Private keys and the keyring master key exist on the machine only inside `keys` ([keys](20-base.md#keys)), which returns none of them. It returns a child's credential once, to `link`, which writes it to the delegating session and keeps no copy, and the unsealed volume key to `store`. Its keys and the purposes of their `KeyUse` capabilities:

| Key | Algorithm | Purpose of its `KeyUse` | Holder of the `KeyUse` |
| --- | --- | --- | --- |
| link key | X25519 static key and an Ed25519 identity key | `handshake`: the responder's Noise_IK operations and the `handshake` signature of the transcript | `link` |
| audit key | Ed25519 | `anchor`: the `anchor` signature of an audit anchor `journal` built | `journal` |
| keyring master key | 256-bit | `node`: sealing values into the [secret records](11-store.md#secret-records) the holder's `View` covers, and opening them for a holder in an isolated space | `store`, and instances in isolated spaces |
| volume key | 256-bit | `volume`: sealing a new volume key with the TPM, and unsealing the sealed key `store` passes from its superblock ([volumes](12-store-format.md#volumes)) | `store` |

- `keys` generates the link, audit and keyring master keys at genesis from the kernel's entropy. On a machine with `tpm`, it keeps them encrypted under a 256-bit key it seals with the TPM, bound to no PCR ([Tpm](15-devices.md#tpm)); otherwise in plaintext in its checkpoint, and `/live/security` reports `key_storage: software`. Code booted on the machine in NaN OS's place unseals that 256-bit key as `keys` does and decrypts the link, audit and keyring master keys with it. `keys` keeps no state for the volume key, which exists only sealed in the store's superblock and, while the volume is mounted, in `store`.
- A **`KeyUse`** capability performs one purpose's operation with one key. Each operation takes that purpose's record type, so no `KeyUse` signs or decrypts arbitrary bytes, and none but `volume` returns key bytes. Its cryptography runs in constant time (requires [N25](22-nan.md#n25)).

### Signatures

[Signatures](02-identifiers.md#hashes) are made with a principal's key, the link key or the audit key. These are the purposes and their signers:

| Purpose | Object | Signers |
| --- | --- | --- |
| `manifest` | a [generation manifest](03-boot.md#generations-and-manifests) | `vendor.*`, `owner` |
| `bundle` | a [bundle](10-code.md#bundle-file) | `vendor.*` |
| `review` | a package's code root hash ([signatures and provenance](10-code.md#signatures-and-provenance)) | the policy's reviewers |
| `seal` | a seal | the policy's sealers |
| `certificate` | a check certificate | the policy's builders |
| `request` | a signed request: an owner key or loader replacement request ([owner key requests](03-boot.md#owner-key-requests), [loader replacement](03-boot.md#loader-replacement)), or a request sent outside a session ([emergency controls](19-oversight.md#emergency-controls)) | `owner` for owner key and loader requests; the principal an `OversightRequest` names |
| `approval` | an approval decision ([approvals](19-oversight.md#approvals)) | `human.*`, `owner` |
| `policy` | the [policy](19-oversight.md#policy) record | `owner` |
| `handshake` | a session challenge's `HelloProof` ([connections and sessions](18-link.md#connections-and-sessions)); the 32-byte Noise_IK handshake hash ([network transports of the link](16-network.md#network-transports-of-the-link)) | the principal opening the session; the link key |
| `anchor` | an [audit anchor](17-observability.md#audit-chain) | audit key |

A signature verifies against the signer's current key; a `former` key also verifies the `bundle`, `review`, `seal` and `certificate` signatures of a bundle blob held at `/sys/code/<hash>/bundle` ([admission record](10-code.md#admission-record)). A signature that does not verify fails with `auth.bad-signature`. `keys` verifies signatures (`verify`) for any instance holding a port to it; a `former` key counts only when the call's `former` is true, which `admission` sets only for such a blob.

### Rotation and revocation

Rotation and revocation are the steps `call keys rotate(...)` and `call keys revoke(...)`, applied only in a plan of an `owner` session or approved by the owner ([approvals](19-oversight.md#approvals)).

- **Rotation** of a principal's key moves the current key to `former` and installs the new public key; sessions the old key opened stay open.
- **Revocation** of a principal's key sets `key` to `None` and empties `former`. The principal's sessions end at once and its grants stay. Admission runs again for every bundle whose admission relied on a signature by a removed key ([admission record](10-code.md#admission-record)).
- Rotation of the link key or the audit key makes `keys` generate a new one. Open sessions continue. The audit entry of the rotation carries the new public key, and the old audit key signs the anchor covering it before the new key signs any.
- The owner key is replaced as [owner key requests](03-boot.md#owner-key-requests) states.

## Capability kinds

NaN OS implements these capability kinds in the kernel, beside NaN's std capabilities (requires [N27](22-nan.md#n27)):

| Kind | Reaches | Attenuations | Semantics |
| --- | --- | --- | --- |
| `Port[P]` | the operations of protocol P of one instance | an operation subset | [ports](07-communication.md#ports) |
| `View` | a store subtree on one branch, with rights `read`, `write`, `admin`, `secret-read` | a subtree, read only, as of a commit | [transactions](11-store.md#transactions) |
| `Control` | the instances under a moniker, with rights `read`, `lifecycle`, `update`, `spawn` | a subtree, a subset of rights | [instances](06-execution.md#instances) |
| `Egress` | outbound flows to destinations matching a pattern | a narrower pattern | [egress gate](16-network.md#egress-gate) |
| `Listen` | inbound flows on one port | none | [ingress](16-network.md#ingress) |
| `KeyUse` | one purpose of one key | none | [keys on the machine](#keys-on-the-machine) |
| `CpuBudget` | a CPU share | a split | [accounting](08-scheduling.md#accounting) |
| `WallClock` | wall time with its uncertainty | a resolution | [clocks](08-scheduling.md#clocks) |
| device capabilities | one device's windows, vectors and DMA | none | [driver instances](15-devices.md#driver-instances) |

NaN's std capabilities are reached through them: `sys::Fs` is a `View` of a dir ([file views](11-store.md#file-views)), `sys::Net` opens flows through `Egress` and `Listen`, `sys::Clock` takes a resolution attenuation (requires [N9](22-nan.md#n9)) and `task::Executor` a share (requires [N8](22-nan.md#n8)). Every capability is a generational handle ([NaN 14 §Capability tables](https://github.com/nan-language/nan/blob/main/docs/spec/14-authority.md#capability-tables)): an attenuation adds an entry deriving from its source's, and an operation through a stale handle fails as [NaN 14 §Revocation](https://github.com/nan-language/nan/blob/main/docs/spec/14-authority.md#revocation) states, the OS kinds failing with `sys::Revoked.Stale` through their error enums.

## Grants

A **grant** is a record conferring authority on a holder, at `/sys/grants/g<n>`, n allocated in commit order and never reused. Capabilities are minted from grants and never persist.

```nan
pub closed struct Grant derives Encode {
    pub holder: Principal
    pub object: Object
    pub rights: mem::Set[Right]
    pub caveats: Caveats
    pub parent: Option[u64] // n of the parent grant
    pub granted_by: CommitId
} Grant

pub closed struct Caveats derives Encode {
    pub budget: Option[u64] // in the object's budget unit
    pub expires_utc_ns: Option[i64]
    pub ask: bool
} Caveats
```

`g0` is the **root grant**: holder `system`, object `Machine`, every right, no parent, written by genesis. Claim writes the owner's grant: holder `owner`, parent `g0`, object `Machine`.

### Objects and rights

```nan
pub closed enum Object derives Encode {
    Machine
    Tree(prefix: Path, branch: text::String)
    Instance(prefix: Moniker)
    Port(prefix: Moniker, operations: mem::Set[text::String])
    Egress(destination: text::String, low: u16, high: u16)
    Listen(port: u16)
    Device(path: text::String)
    Clock
    WallClock
    Random
    Exec
    Key(purpose: text::String)
    Principals(prefix: text::String)
    Session(share: Share, budget: SessionBudget)
} Object

pub closed enum Right derives Copy, Eq, Ord, Encode {
    Read
    Write
    Admin
    SecretRead
    Lifecycle
    Update
    Spawn
    Parallel
    Fine
    Enroll
} Right
```

| Object | Rights | Mints | Budget unit | Covers |
| --- | --- | --- | --- | --- |
| `Machine` | all | every kind | none | everything |
| `Tree` | `read`, `write`, `admin`, `secret-read` | `View` | bytes written per day | the nodes under `prefix` on `branch`, on every branch for `*` |
| `Instance` | `read`, `lifecycle`, `update`, `spawn` | `Control` | bytes of memory limits of the specs it creates | the instances named `prefix` or under it |
| `Port` | none | `Port[P]` of each covered instance's protocol | none | the `operations`, all when empty, of the instances named `prefix` or under it |
| `Egress` | none | `Egress` | bytes per day | flows to `destination` on ports `low` to `high` |
| `Listen` | none | `Listen` | none | inbound flows on `port` |
| `Device` | none | the device capability | none | the device at the bus path ([device discovery](15-devices.md#device-discovery)) |
| `Clock`, `WallClock` | `fine` | `sys::Clock`, `WallClock` | none | the clock at its own resolution, except at 1 ms for a job of provenance `agent` without `fine` ([worlds](06-execution.md#worlds)) |
| `Random` | none | `sys::Random` | none | the kernel's entropy |
| `Exec` | `parallel` | none | none | with `parallel`, the parallel executor for a job of provenance `agent` ([worlds](06-execution.md#worlds)) |
| `Key` | none | `KeyUse` | none | the key purpose `purpose` |
| `Principals` | `enroll` | none | none | enrolling principals named `prefix` or under it, `prefix` being a principal or a kind prefix such as `agent` |
| `Session` | none | none | none | opening sessions with that [share](08-scheduling.md#shares-and-reservations) and [session budget](18-link.md#budgets) ([sessions as authority](#sessions-as-authority)) |

- A right is written `<object>.<right>` in lower case in policy rules and output: `tree.write`, `exec.parallel`, `clock.fine`.
- `Tree`: `read` covers reads, queries, diffs, history and watches, on every path except `/state/keys`; `write` covers writes and deletes, and `admin` branches, merges and pins ([branches](11-store.md#branches)); neither covers `/sys`, `/state`, `/live`, `/journal` or `/history`, whose nodes their owning operations write. `secret-read` lets a `View` held in an isolated space read the plaintext of secret records ([secret records](11-store.md#secret-records)).
- `Instance`: `spawn` creates and deletes specs, `lifecycle` starts, stops, hibernates and wakes, `update` changes bundles, `grants`, `wiring` and `/sys/config` records, and `read` reads specs, configuration, `/state` and `/live/instances`.
- `destination` is a host name; `*.` and a domain, matching its subdomains; or an address with a prefix length (`10.0.0.0/8`, `fd00::/8`). A host pattern matches flows opened by name, an address pattern the peer address.

### Caveats

- `budget` bounds what the capabilities minted from the grant consume, in its object's unit; a daily budget restarts at 00:00 UTC. An operation exceeding it fails with `auth.budget-spent`.
- `expires_utc_ns` is a scheduled revocation ([revocation](#revocation)).
- `ask` makes each plan step using the grant need approval, whatever the [policy](19-oversight.md#policy) rules decide.

### Validity

A grant's **writer** is the principal of the plan writing it, or the instance writing it through its own capabilities. A plan step `grant` ([steps](14-changes.md#steps)), or a write of a grant, is refused unless:

1. its holder is a principal with a record, `system`, or `inst.<moniker>` with a spec (`auth.unknown-holder`);
2. its parent is a live grant (`auth.unknown-parent`) held by the writer or by an instance acting for it (`auth.not-holder`);
3. its holder is a child of the writer or an instance acting for it, or the writer is `owner`, acts for `system`, or holds a `Principals` grant with `enroll` covering the holder (`auth.wrong-holder`);
4. each right, and a budget caveat, is one its object takes (`auth.bad-right`);
5. it lies **within** its parent: its object is covered by the parent's (a prefix under the parent's prefix, a subset of its operations, a destination and port range inside its own, the same device, purpose or port, anything under `Machine`), its rights are a subset of the parent's, the budgets of the parent's children sum to at most the parent's, its expiry is at or before the parent's, and it has `ask` when the parent has. A `Session` object lies within a parent `Session` when its share's class is at most the parent's (`Background` < `Normal` < `Latency`), each other field of its share and of its budget is at most the parent's, `None` counting as unlimited, and the consumable budget fields (`output_units`, `cpu_ms`, `memory_bytes`, `egress_bytes`, `energy_mj`, `infer_tokens`, `infer_micros`) of the parent's children sum to at most the parent's (`auth.not-within`).

The holder of the grant or of one of its ancestors, and `owner`, may revoke a grant; any other `revoke` step is refused (`auth.not-revoker`).

## Delegation

`delegate <delegation>` ([session verbs](18-link.md#session-verbs)) creates a **child principal** of the session's principal, which is a human, an agent or a child (`auth.not-delegator`), from a `Delegation`, in one commit:

```nan
pub closed struct Delegation derives Encode {
    pub child: Option[text::String] // the last segment of the child's name
    pub grants: mem::List[ChildGrant]
    pub budget: SessionBudget
    pub expires_s: Option[u32]
} Delegation

pub closed struct ChildGrant derives Encode {
    pub object: Object
    pub rights: mem::Set[Right]
    pub caveats: Caveats
    pub parent: u64 // a grant the delegator holds
} ChildGrant

pub closed struct AuthConfig derives Encode {
    pub child_expiry_h: u32
} AuthConfig
```

1. It names the child `<principal>.<child>`, `child` being `c<n>` when absent, n the lowest free number; `child` is a `MONIKER_SEGMENT` of at most 24 characters ([monikers](02-identifiers.md#monikers); `request.invalid-operand`). A name over 64 bytes fails with `auth.name-too-long`, an existing name with `auth.name-taken`.
2. `keys` generates an Ed25519 key pair (`issue`, [keys](20-base.md#keys)); the child's record holds the public key, `parent` and `expires_utc_ns`.
3. It writes the child's session grant, whose parent is the delegator's session grant or `Machine` grant, with `budget` and the delegator's share; a `Tree` grant with `write` on `/data/<delegator>/inbox/<child>`, which it creates ([/data](13-tree.md#data)); and one grant per `ChildGrant`. Each is valid by [validity](#validity).
4. It returns the child's name and its 32-byte private key seed, once; `keys` keeps no copy.

A child expires `expires_s` after its delegation, by default 24 hours (`AuthConfig.child_expiry_h`, at `/sys/config/auth`, which `link` applies, as it performs `delegate`), and at or before its delegator's expiry; each of its grants expires at or before the child. At its expiry, at its delegator's removal and at the revocation of its delegator's key, the child is removed with its own children, grants and sessions; its results stay in its inbox.

## Revocation

A plan step `revoke g<n>` removes the grant and every grant descending from it, in one commit.

- The core keeps one **root entry** per live grant, and every capability minted from the grant derives from it. The core revokes the root entries of a commit's removed grants before the commit is acknowledged, so no capability check starting after the acknowledgement passes: every copy of those capabilities is stale at once ([NaN 14 §Revocation](https://github.com/nan-language/nan/blob/main/docs/spec/14-authority.md#revocation)).
- The core arms one timer at the earliest expiry among live grants, except on an [idle machine](08-scheduling.md#idle-machine), whose next wake-up first revokes the grants whose expiry passed. When the wall clock's time plus its uncertainty reaches a grant's expiry, the core revokes its root entry and its descendants', and `supervisor` commits their removal as `system`. At boot, grants past their expiry are removed before any capability is minted.
- An instance keeps running when a capability in its Env goes stale; operations through it fail, and its next start fails as [starting](06-execution.md#starting) states unless its spec changes.
- Each removal emits `auth.revoked` and is an entry of the [audit chain](17-observability.md#audit-chain).

## Env construction

The runner builds an instance's Env at every start, restore, revival and update ([starting](06-execution.md#starting)) from its spec's `grants`, which map Env fields to grant numbers, its `wiring`, which maps Env fields to wires ([wiring](07-communication.md#wiring)), and the instance's configuration record at `/sys/config/<moniker>`. Capabilities derive no `Encode`, so none outlives a restart or a reboot: after a reboot, authority is exactly what the records describe.

1. A field of type `mem::Alloc`, `task::Executor` or `sys::Log` receives the instance's cell, executor and journal stream.
2. A field named in `grants` receives a capability minted from that grant, which must be live, held by `inst.<moniker>` and of an object minting the field's kind. A `Device` grant yields runner-held resources ([runner tables](06-execution.md#runner-tables); requires [N28](22-nan.md#n28)).
3. A field named in `wiring` receives the port its wire mints ([wiring](07-communication.md#wiring)). That port derives from the lowest-numbered live grant, held by the instance or by the principal it acts for, that covers the wire's target: a `Machine` or `Instance` grant, or a `Port` grant whose operations hold the wire's. A `Port` grant named in `grants` mints a port to the instance its `prefix` names.
4. A field named `config` receives the configuration record, decoded as the component's **configuration type**: the field's type, or the type its `Option` holds, which the component's [admission record](10-code.md#admission-record) names.
5. Each capability is minted through one `sys::Revoker` per instance and grant, deriving from the grant's root entry, and the Env is built through the bundle's component entry (requires [N1](22-nan.md#n1)).

An `Option` field without a source receives `None`. Any other field without a source, a field whose source mints another kind, and a `config` field whose record does not decode as the configuration type fail as [starting](06-execution.md#starting) states. The preview of a plan writing a spec's `grants` or `wiring`, a configuration record, or a grant, runs these checks against the tree the plan yields; a plan writing a wire that no grant of its principal covers is refused (`auth.denied`), and any other failing plan as starting states.

## Sessions as authority

A principal opens sessions ([connections and sessions](18-link.md#connections-and-sessions)) only while it holds a live `Session` grant, its **session grant**, or a `Machine` grant; it holds at most one `Session` grant (`auth.wrong-holder`). Its sessions take their [budget](18-link.md#budgets) and their accounts' share ([accounting](08-scheduling.md#accounting)) from that grant, or under `Machine` the budget of `LinkConfig` ([configuration](18-link.md#configuration)) and the default share; what they consume counts together against that budget. Each session ends when that grant expires or is revoked.

A session acts with exactly its principal's grants. Its **root capability** is the set of capabilities minted from those grants, all deriving from one revoker the session owns; ending the session revokes them at once. A grant added to or removed from the principal takes effect in its open sessions at once. A request needing authority none of them confers fails with `auth.denied`, naming the right it needs.

## Provenance

The **provenance class** of a bundle is computed at admission from its signatures ([signatures and provenance](10-code.md#signatures-and-provenance)), in this order:

1. `vendor`: the kernel image's base bundle, or a bundle carrying a `bundle` signature by a `vendor.*` principal with a record.
2. `reviewed`: every package of its closure outside std carries a `review` signature by a **reviewer**, a `human.*` or `owner` principal the [policy](19-oversight.md#policy) names as reviewer, and every trust escape of the closure a `seal` signature by a reviewer who is an author of neither the sealed item's package nor any package holding an item of its closure entries ([NaN 31 §Seals](https://github.com/nan-language/nan/blob/main/docs/spec/31-trust.md#seals)).
3. `agent`: every other bundle, every one built from source an `agent.*` principal wrote included, whatever the taint of its session.

```nan
pub closed enum Provenance derives Copy, Eq, Encode {
    Vendor
    Reviewed
    Agent
} Provenance
```

The **authors** of a package are the principals its provenance section names (requires [N15](22-nan.md#n15)); for a bundle the `nan` job builds on the machine, admission records instead the principals of the commits that wrote the package's sources. A change of the policy recomputes the class and the `shared` field of every admitted bundle it affects; an instance whose placement changes restarts in its new space (`place.moved`).

## Placement

Placement is computed when an instance starts, from its bundle's [admission record](10-code.md#admission-record), the principal it acts for, the policy and the machine. An instance runs in the **shared space** only when:

1. its bundle's provenance is `vendor` or `reviewed`, or `agent` with no trust escape in its closure under a policy allowing agent code in the shared space (`agent_shared_space`, [policy](19-oversight.md#policy)) on a machine with `iommu`;
2. every trust escape of the closure carries an accepted seal by a `vendor.*`, `human.*` or `owner` principal;
3. its Env holds no `KeyUse` capability other than those genesis wires into base instances;
4. it acts for `system` or `owner`;
5. its spec's `placement` is not `isolated`.

Admission records conditions 1 and 2 as the bundle's `shared` field. Every other instance runs in the **isolated space** of its principal and provenance class, one space per pair, named `<principal>/<class>` in `/live`. `keys` runs alone in the isolated space `keys`; the other base instances run in the shared space. The mechanics of spaces are [placement mechanics](04-kernel.md#placement-mechanics); isolated spaces require [N23](22-nan.md#n23).

### Machine conditions

- On a machine without `user-mode`, a step starting an instance placed isolated is refused (`place.unavailable`), except for `keys`, which runs in the shared space and is reported `/live/security` `keys: unconfined`.
- On a machine without `iommu`, the machine is one trust domain for DMA: no device grant is confined, so each needs a vendor or human seal ([admission](10-code.md#admission)), a driver whose bundle is of class `agent` is refused (`place.device-unconfined`), the `autonomous` preset is unavailable, and `/live/security` reports `dma: unconfined`.
- On a machine with `iommu`, a device capability confined to its device's IOMMU domain is no trust escape (requires [N13](22-nan.md#n13); [DMA and IOMMU](15-devices.md#dma-and-iommu)).

## Confidentiality of the shared space

The shared space is one confidentiality domain: an instance in it may read anything another instance in it holds.

- No private key but a child's credential on its way to the delegating session ([delegation](#delegation)), no keyring master key and no [node key](11-store.md#secret-records) is ever in the shared space's memory, and no instance in it decrypts a secret record: a `KeyUse(node)` held there only seals, and the plaintext of a secret record reaches only the holders that [secret records](11-store.md#secret-records) names. A plaintext a session writes into a secret record passes through `link` and `store` to `keys`.
- The transport keys of the link's open sessions, the volume key and a child's credential on its way to the delegating session are the only key material in the shared space.
- On a machine without `user-mode`, `keys` runs in the shared space ([machine conditions](#machine-conditions)), and the two rules above hold outside its memory.
- Isolation covers memory, not channels through shared resources: commit latency, memory pressure levels and CPU time leak between spaces at a rate this specification does not bound.

## Costs of isolation

| Cost | Paid when | Size |
| --- | --- | --- |
| encoding and validating decode | each message between spaces, as between bundles ([isolated transport](07-communication.md#isolated-transport)) | the cost of a [transfer](07-communication.md#transfer) between bundles |
| split tables | each crossing between an isolated space and the core, on a machine without `meltdown-immune` | two root loads per crossing ([split tables](04-kernel.md#split-tables)) |
| TLB flush | each switch between spaces, on a machine without `pcid` | the CPU's non-global translations |
| IBPB | each switch between isolated spaces of different principals (requires [N11](22-nan.md#n11)) | one barrier |
| core scheduling | on a machine whose measured fact `smt` holds, the core scheduling of [wake placement](08-scheduling.md#wake-placement) | the siblings' idle time |
| memory | each isolated space | its page tables, its user-mode runtime and its copy of each loaded bundle's writable data |

An instance in the shared space pays none of these.
